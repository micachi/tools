Intune Win32 検出ルール 生成

Win32 アプリ展開の検出ルール（Detection rules）を検証し、全条件を AND で満たしたときだけ「検出」とみなす カスタム検出 PowerShell を生成します。ルール種類・必須フィールド・特殊文字の制約は公式ドキュメント準拠です。

検出の契約（カスタムスクリプト）

終了コード STDOUT Intune の判定
0文字列あり検出（インストール済みとみなす）
0出力なし未検出（未インストールとみなす）
0 以外—エラー（検出失敗・展開は継続されない）

スクリプトの既定タイムアウトは 60 秒。超過は検出失敗になります。重い処理（Win32_Product の全列挙など）は避けてください。

ルール型の決まり（公式）

  • ルールは最低 1 個必要。0 個では展開できません
  • 複数ルールは AND — 全ルール条件を満たすことが検出の条件です（OR は組めません）
  • MSI — プロダクトコード（GUID）で照合。追加は 1 回のみ。バージョン確認も選択可
  • ファイル / フォルダ — Path に , や " など一部の特殊文字を含めると検出が壊れます
  • レジストリ — Key path は HKEY_LOCAL_MACHINE\… / HKLM\… 形式。Value name 空ならキーの存在で検出
  • 64bit クライアントで 32bit アプリのパス／レジストリを検出する場合は「32bit ファイル システム / レジストリ」のラップを考慮（Program Files (x86)・Wow6432Node）
  • アプリ未検出の場合、required intent のアプリは約 24 時間以内に再提供されます

参考: Microsoft Learn — Add Win32 apps / Step 4: Detection rules

よくある落とし穴

  • 検出ルールが広すぎる → 旧バージョンを検出したまま「インストール済み」となり、更新が当たりません。バージョン条件を必ず入れる
  • 検出ルールが狭すぎる → 展開後に条件が崩れる（ログ削除・パス移動など）と、毎回再展開ループになります
  • MSI を「ファイル存在」で代用する → 別ミドルウェアの同パスファイルを拾うことがあります。MSI は MSI で検出してください
  • PowerShell を「出力あり＝成功」で書き忘れる → 出力がないと常に未検出になります（本ツールは最後に必ず Write-Output を置きます）
