Intune OMA-URI / Windows CSP Lookup

Find and compose the OMA-URI used by Intune custom settings, from the official “Graph API property → Windows CSP” mapping (732 entries). An OMA-URI is CSP root + Offset URI, validated for the leading ./ and the Vendor/MSFT/ segment.

OMA-URI builder

What the scope means

  • ./Device/Vendor/MSFT/… — device scope; settings that do not vary per user
  • ./User/Vendor/MSFT/… — user scope; applied to the signed-in user
  • ./Vendor/MSFT/… — both Device and User; determined by what you assign it to

A custom OMA-URI setting is the last resort for settings missing from the UI. Check the settings catalog and policy templates first.

Frequently used CSP roots

  • ./Device/Vendor/MSFT/Policy/Config/… — the policy family (equivalent to Administrative Templates)
  • ./Device/Vendor/MSFT/BitLocker/… — BitLocker encryption
  • ./Device/Vendor/MSFT/Firewall/… — Windows Firewall profiles
  • ./Device/Vendor/MSFT/PassportForWork/… — Windows Hello for Business
  • ./Device/Vendor/MSFT/AssignedAccess/… — kiosk / assigned access
  • ./Vendor/MSFT/Defender/… — Microsoft Defender (Device and User)

Source: Microsoft Learn — Graph APIs and matching Windows CSPs used in Intune ／ CSP details: Windows MDM CSP reference

Operational notes

  • An entry may have more than one Offset URI — the selector above lists every candidate
  • Getting the data type wrong means the setting never applies — confirm integer / string / boolean / XML in the CSP reference
  • A doubled slash after joining is the most common error — this tool trims the trailing slash before concatenating
  • The mapping is Graph-driven — it shows how Graph entities map to CSPs, not an exhaustive CSP catalogue
